# Отчёт по API-тестированию (WMS — складская система)

**Автор:** Валерий Яманкин  
**Дата:** 10.08.2026  
**Инструмент:** Postman v10.18  
**Тип тестирования:** Функциональное, интеграционное, негативное  

---

## 1. Объект тестирования

**Базовый URL:** `https://api.demo-warehouse.ru/api/v1`  
**Метод авторизации:** Bearer Token (JWT), полученный через `/auth/login`  
**Формат данных:** JSON  

В рамках тестирования проверялись ключевые эндпоинты системы управления складом (WMS), отвечающие за:
- Управление товарами и остатками,
- Обработку заказов,
- Приёмочные операции.

---

## 2. Список проверок (Коллекция Postman)

| № | Метод | Эндпоинт | Описание сценария | Ожидаемый код ответа | Статус |
|---|-------|----------|-------------------|----------------------|--------|

## 3. Детали выполнения негативных проверок

### Проверка 6 (Отрицательное количество)
- **Запрос:** `{"productId": 1001, "quantity": -5, "warehouseId": 1}`
- **Результат:** Сервер вернул 400 с сообщением `"Количество должно быть положительным числом"` — валидация работает корректно.

### Проверка 11 (Повторное удаление позиции) — **НАЙДЕН ДЕФЕКТ**
- **Запрос:** `DELETE /orders/123/items/456` (выполнено дважды).
- **Ожидание:** При повторном запросе сервер должен вернуть 404 (Not Found), т.к. ресурс уже удалён.
- **Факт:** При повторном DELETE сервер возвращает **500 Internal Server Error** (NPE в коде).
- **Баг заведён:** BUG-004 в Jira.
